Shell & nav

tier 1 — the frame

The layout chrome: shell, sidebar, nav, topbar, user widget. This must look identical in every app, and nobody — human or AI — should restyle it per project.

Use the components; the classes are the fallback. <AppShell>, <Sidebar>, <NavItem>, <AppHeader> and <UserWidget> emit exactly the markup shown on this page, so the two are interchangeable and a test asserts they stay that way. Write the classes by hand only where a component does not cover what you need. Either way, do not add local overrides for the frame — report frame problems against the library.

The same shell, as components

Add @using DR.Simple_UI.Components to your _Imports.razor once. <AppShell> renders .layout > .content > .page and <AppHeader> always emits the spacer that pushes the trailing controls to the far edge, so neither is something you can forget.

<NavItem> tracks the current address itself and sets aria-current="page" as well as the active class — the framework's own <NavLink> sets only the class. The link to the root needs Match="NavLinkMatch.All", or it is active on every page. It is called NavItem and not NavLink because NavLink is already in scope in every Blazor app, and shadowing it would break every existing use.

<ChildContent> is spelled out, and it is not optional. As soon as a component has one named RenderFragment parameter, Razor stops accepting loose child content and fails the build with RZ9996 — so <AppShell> (which has Navigation and Header), <Sidebar> (Tools) and <AppHeader> (Start) all need it. The user's details are bound to fields for a related reason: an e-mail address written straight into an attribute is read as a C# expression at the @@, which fails with RZ9986.

Full shell

.layout is the flex row that fills the viewport; .content is the column beside the sidebar; .page is the only scroll container. Shown here at a fixed height — in an app the layout fills the window.

Collapsed rail

Add .collapsed to .sidebar — no other markup changes. Labels and status text drop out, the count pill moves onto the icon, and each item's data-tip becomes a CSS flyout that escapes the 56px rail. Hover an icon to see it.

Narrow screens

Add .layout--responsive to .layout and the sidebar becomes the rail below 900px, whether or not .collapsed is set. The user widget drops its second line at 900px and its whole text block at 560px, leaving the avatar.

Opt-in on purpose. Collapsing the sidebar automatically would change how every already-released app looks on a narrow screen with nobody editing anything. The modifier also outranks an app that sets .sidebar { width: 260px } unconditionally — a bare @media rule would lose to it on source order.

Note that below 900px a collapse toggle does nothing, because the rail is forced. Hide the toggle at that width, or leave it and accept the no-op.

User menu

The panel is the library's one dropdown style, .menu — see Menus for its items, labels and separators. There is not a second panel style for the header. Only the anchoring belongs to the frame: .user-widget is already position:relative, so the panel hangs off the header's bottom edge with nothing measured and no anchor positioning, which Firefox ESR does not have. Shown here open; <UserWidget> handles opening, the outside click and Escape.

It is a disclosure, not an ARIA menu: the items are ordinary links and buttons that tab normally. Declaring role="menu" would promise arrow-key navigation and a roving tabindex, and claiming that without implementing it is worse than claiming nothing.

The component also emits .menu-scrim immediately before the panel — a transparent full-viewport element that catches the click dismissing the menu. It is deliberately left out of the demo below, because a fixed element covering the viewport would swallow every click on this page. It carries no z-index: coming first in the markup is what puts the panel above it.

Bare shell

.bare-layout — topbar and body, no sidebar. For sign-in, access-denied and error pages, where there is no navigation to offer yet.

Reconnect banner

Supply all three banner rows in your host page; Blazor Server toggles the state classes on #components-reconnect-modal itself, and each row is hidden until its own state is the current one. Shown here with those classes applied. The banner stays dark in the light theme, because a connection failure should look the same wherever it happens.

.reconnect-rejected is the one that gets forgotten. It is not a failed attempt — the server answered and refused, because the circuit is gone for good, so reconnecting cannot help and only a reload will. Omit the row and that state renders as an empty bar.

Hover hints. Add data-tip="what it does and its consequence" to actionable controls, plus aria-label on icon-only buttons. DR.Simple_UI.js renders one bubble for the whole page through event delegation, so content rendered later needs no wiring. Use data-tip-pos="left|right|top|bottom" to set a side. Elements inside .sidebar are skipped; the collapsed rail uses a CSS flyout instead.
