Chips & avatars

tier 2 — classes

Small inline objects. A .chip is a thing the user put there and can take away; an .avatar is who did something. Neither is a badge, which describes a state and is read-only.

Chip or badge? Ask whether the user can remove it. If they put it there and can take it away, it is a chip. If it reflects data, it is a badge. Getting this the wrong way round gives you a page of pills where nobody can tell which ones are clickable.

Chips

.chip-set wraps a row of them. The remove button is a real <button> and needs a real name: × on its own is announced as “times” and says nothing about what it removes, so write aria-label="Remove Service desk".

A chip with no dismiss button drops the trailing room for one, so a static chip is not lopsided.

Avatars

An <img>, initials, or a Remix Icon — in that order of preference. The icon is the honest fallback; a generated colour block invents a distinction that is not in the data.

An avatar is never the only carrier of a name. Put the name in text beside it, in an alt, or in a .visually-hidden span. Initials are not a name, and a title tooltip is reachable by neither keyboard nor touch.

Avatar group

Overlapping, for “these several people”. The separating ring is a box-shadow rather than a border, so it does not change the box size and the overlap stays exact. The counter is not an avatar: it is a number, and giving it the brand tint would make it look like one more person.
