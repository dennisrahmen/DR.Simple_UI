Drawers, palette & spotlight

tier 2 — classes

Three surfaces that come over the page. All three prefer a real <dialog>, because the platform then supplies the focus trap, Escape and inert content behind — and a hand-rolled focus trap is a lot of code that is usually subtly wrong.

Drawer or modal? A modal demands an answer before anything else happens; a drawer is a place to work that can be left. If dismissing it loses nothing, it is a drawer. The drawer sits below the modal backdrop in the z-order on purpose, so a modal opened from inside a drawer still covers it.

Drawer

Shown here inline and open, with position:static, so the page stays usable. In an app it is fixed to an edge. .drawer-body is the only scrolling part, so the header and footer stay put.

Closed state is visibility:hidden, not just a translate off-screen: a panel that is merely moved away is still tabbable, and Tab then walks the reader into a panel they cannot see. .drawer--start comes from the other edge; .sheet comes from the bottom, which is the right shape on a phone where a side panel has nowhere to come from.

Drawer as a <dialog> — the preferred form

A drawer with a scrim is modal in behaviour: the page behind it should not be reachable. So say so, and let the platform do it. showModal() gives the focus trap, Escape and inert content behind, and ::backdrop replaces .drawer-scrim entirely.

.drawer-scrim and .drawer-scrim--open remain for a drawer that is deliberately not modal — one you can leave open while working on the page behind it. Then you own the dismissal and the focus handling.

Command palette

The Ctrl+K box. Positioned near the top rather than centred, because the list grows downwards and a centred box would move under the reader's eye as they type.

The list is a real role="listbox" of role="option" items, with the input as the combobox owning it through aria-activedescendant. That claim is made only because drSimpleUi.palette implements the keyboard contract behind it in full — and because aria-selected on a plain button is invalid, which axe rejects. aria-selected is the keyboard's position, which is a different thing from :hover: moving the pointer must not move the keyboard.

Palette markup

A <dialog> again, which is why the CSS is this small: the top layer, the focus trap and Escape are all the platform's. .palette-empty is the no-matches state — say what was searched, not just “no results”.

There is no fuzzy-match library and there will not be one: a subsequence scorer is about twenty lines, and this package loads nothing at runtime.

Spotlight

Dims the page except one element, for a guided tour or a first-run hint. The hole is a box-shadow with a 100vmax spread rather than a clip-path or four dimming strips: one element, no arithmetic, and the ring follows the highlighted element's own border radius.

pointer-events:none on the dim, so the highlighted control stays operable — a tour that blocks the thing it is pointing at teaches nothing. Shown here inside a bounded box; in an app the app positions the hole over its target.
